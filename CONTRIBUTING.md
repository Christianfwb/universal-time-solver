# Contributing

Thank you for improving Universal Time Solver.

1. Open an issue describing the change.
2. Use the ontology’s definitions for internal analysis; label external comparisons separately. See [analytical scope](docs/ANALYTICAL_SCOPE.md). Keep numerical relations separate from ontological interpretation.
3. Add tests for code changes.
4. Run the test suite before opening a pull request.
5. Do not present internal consistency as independent experimental proof.

Small corrections, translations, reproducible examples and falsifiable test proposals are welcome.
